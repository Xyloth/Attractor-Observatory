# Doctrine D7-D13: Truth Pass and Substance Budgets

## D7. No Toys

A world implementation file with fewer than 400 lines of substantive simulation
code is `mode: stub`. Stubs cannot anchor claim-bearing gates, contribute to
AttractorStrength implementation diversity, or satisfy cross-family transfer.

## D8. No Number-Generator Corpora

Every K-corpus scenario must produce a runnable trace from a real world.
Detectors read trace state, events, lineage, and ledgers, never scenario payload
fields such as `signal_strength`.

## D9. No Engineered Pass Criteria

Lens predictions are derived from the encoded representation by the lens's own
procedure. Hand-tuned linear coefficients on event counts are heuristics and are
not formal predictions.

## D10. No Hardcoded Science

Representability and schema-pressure scores are measured by running predicates
against active artifacts, not by set membership hardcodes.

## D11. Truth Pass Required Before New Claims

Any candidate artifact whose evidence chain passes through a stub or
number-generator is downgraded to exploratory until reconstruction and
world-driven calibration pass.

## D12. Gates Are Measurements, Not Counts

Counts may be preconditions. Gates require a quantity, threshold, comparison,
source, and measured value.

## D13. Substance Budgets Stay Honest

Each builder task records per-module substance: simulation logic, trace export,
scaffolding, and tests.
