# The central correction for v1.2

The most important v1.2 change:

# Add the No Artificial Ceiling Doctrine as an architectural principle

Claude’s v1.1 has task sizing and red flags, but it lacks the doctrine you just made canon.

That doctrine needs to appear near the top of v1.2, before module boundaries, before task atoms, before Codex instructions.

I would insert this as **Section 0.1**:

```text
0.1 No Artificial Ceiling Doctrine

Every specification, task description, architecture note, and implementation request is a seed and a minimum standard, not a ceiling.

Scientific invariants protect claims; they do not limit implementation ambition.

A coder may exceed the requested scope when doing so improves correctness, observability, extensibility, testing, reproducibility, or scientific value.

Task boundaries define the minimum successful artifact, not the maximum permissible contribution.

Review exists to refine ambitious work, not to prevent it.

The project prefers overbuilt, well-instrumented, creatively rigorous implementations that can be pruned over narrow compliance implementations that must be repeatedly expanded.

Seed, not ceiling.
Minimum, not maximum.
Trust the builder.
```

Then every Codex task atom should include:

```text
minimum_success:
builder_expansion_authority:
suggested_extensions:
review_triggers:
claim_safety_invariants:
```

Not just:

```text
out_of_scope
red_flags
```

Because “out_of_scope” and “red_flags” are psychologically shrinking fields.

Replace them with:

```text
claim_safety_invariants
review_triggers
```

That preserves rigor without capping ambition.

## It confuses “phase gates for scientific claims” with “phase gates for building”

Claude says things like:

Rules:

```text

calibration
nulls
provenance
determinism
bias correction
review
```

This solves the contradiction.

Claude’s rigor belongs to **claim-bearing mode**.

Your builder doctrine belongs to **exploratory build mode**.

Both are needed.

v1.2 should say:

```text
No phase gate may block exploratory implementation.
Phase gates only block claim promotion.
```

That is the key sentence.

## Amendment 8 — Reframe AttractorStrength as multi-objective first, scalar second

Claude improved the v1.0 product score into a weighted log-additive composite. That is good.

> The vector is primary. The scalar is a report convenience.

The score should always show:

```text
R recurrence
P persistence
B basin width
X cross-family transfer
D implementation diversity
I detector-ablation invariance
C_pred predictive contribution
S_obs sampling sufficiency
F formal coverage
G formal gap
```

But candidate attractors should also be ranked by Pareto status:

```text
Pareto-dominant
Pareto-front
specialist attractor

```

One scalar can hide this.

So v1.2 should say:

```text
AttractorStrength is reported as a vector and optionally projected to scalar summaries for specific claims.
No scalar ranking is canonical across all use cases.
```
